# Threat model

Protected assets include private documents, identity/session material, tenant metadata, and citations. Principal threats are IDOR, forged organization IDs, cross-collection leakage, prompt injection in sources, malicious uploads, replayed writes, credential theft, log disclosure, denial of wallet, and incomplete deletion.

Controls include server-derived tenant context, centralized RBAC, collection filtering before prompt assembly, size/checksum validation, idempotency keys, strict origin/cookie policy, short-lived upload grants (enforced ten-minute expiry), hashed invitation tokens, fail-closed timing-safe service authentication between Workers, verified-email gating for platform administration, per-workspace daily request and monthly OCR budgets, structured redacted logging, and immediate multi-store purging (Vectorize, then D1 chunk rows with FTS triggers). Evidence passed to the model is wrapped in explicit `<evidence n>` delimiters and the system prompt forbids following instructions inside it; like all prompt-injection mitigations this reduces, but cannot eliminate, the risk. Note that indexed chunk text is client-supplied by workspace editors and is not re-derived server-side from the uploaded file, so any editor can influence retrieved evidence; BYOK provider-key storage and bearer API keys are designed but not yet implemented.

Security-sensitive changes require tenant-isolation tests and a purge-completeness test — see `apps/ai-worker/src/retrieval.integration.test.ts` and `packages/db/src/migrations.test.ts`. Rotate `BETTER_AUTH_SECRET` and the service token through staged rollout; never print them. Report vulnerabilities privately to the repository owner.
